## 2. Выводы, из которых собран текст

1. **Нельзя задавать вопросы.** Человек, который никогда не комментирует в трекере, не ответит на «готов ли ты
   принять?». В v1 было три вопроса — это гарантированное молчание. Во v2 вопросов нет; есть готовый к применению диф.
2. **Доказательство должно быть машинным, не человеческим.** Раз построчного review нет, работающий аргумент — только
   тот, что проверяется его же CI (`check_seams.py` + `build`), плюс GameTest. Называть числами.
3. **Форма тела — как у его собственных слитых PR** (`## Summary` / `## Key Changes` по файлам / `## Verification`):
   к этому формату он уже приучен своей же историей merge.
4. **Аргумент — паритет с оригиналом, а не наша нужда.** Его заявленная цель — точность порта. В 1.7.10 аспект создавался
   `new Aspect(...)`, значит расширяемость в оригинале была, а enum — регресс порта. «Сделайте API для моего аддона»
   слабее, чем «порт отклоняется от оригинала в точке X».
5. **Приор-арт снимает ощущение экзотики:** соседний TC4 Reconstructed уже возит аддон-аспекты как данные и 32 аддона.
6. **Нулевая стоимость для него:** мы зависим от `thaumcraft >= 1.2`, поэтому его следующий релиз сам по себе
   разблокирует порт FM — ему не надо ничего делать для экосистемы, кроме как смержить или отклонить диф.
7. **Маленький диф.** +233/−96 в 7 файлах против его же 13–17 тыс. строк в слитых PR.

## 4. Текст issue (готовая вставка)

```markdown
## Summary

В оригинале 1.7.10 аспект создавался в рантайме — `new Aspect(tag, color, components, texture, blend)`
(например, так аддон Forbidden Magic объявлял свои семь аспектов грехов). В порте `Aspect` — `enum`
из 48 констант, и добавить аспект извне нельзя: Java не позволяет добавить константу enum из другой
сборки. Это отклонение порта от оригинала в точке, которая уже закрыта для аддонов.

Предлагаемый диф превращает `Aspect` в `final class` с реестром и добавляет один хук регистрации для
сторонних аддонов. Публичный интерфейс не меняется: `Aspect.FIRE`, `AspectList`, `Aspect.values()`
работают как раньше.

## Key Changes

**0001 — `Aspect` enum → реестр** (3 файла, +173 / −96):
- `aspect/Aspect.java`: `final class` с внутренним реестром — `register`, `values`, `byOrdinal`,
  `builtinCount`, `Codec` по тегу. Все 48 констант, их имена, порядок и ординалы сохранены.
- `wand/WandVis.java`: два `switch (aspect)` (`:32 get`, `:44 with`) переписаны — это единственные
  switch-по-аспекту в кодовой базе.
- `entity/AspectOrb.java`: чтение индекса аспекта идёт через `byOrdinal`.

**0002 — хук для аддонов** (4 файла, +60 / −0):
- `aspect/AddonAspects.java` — новый класс: `register(tag, color, components, blend, texture)` и
  `addRegistrar(...)`; идемпотентен, работает на клиенте и сервере.
- `aspect/AspectRegistrar.java`, `aspect/AspectRegistry.java`, `aspect/AspectSync.java` — вызов в
  `rebuild` до пересборки реестра.

## Verification

На пине `69a47a1` (HEAD `main`, тег `26.3`), патчи 0001+0002 применены к копии дерева:

- `python3 tools/check_seams.py` → `seams ok: 932 files checked`
- `./gradlew build` → `BUILD SUCCESSFUL`
- `./gradlew runGameTestServer` → `All 256 required tests passed :)`

Совместимость проверена по всему `src/main/java` на стоковом дереве:

- 4118 обращений вида `Aspect.<КОНСТАНТА>` — ни одно не меняет текста (`Aspect.FIRE` остаётся валидным статическим
  полем `final class`);
- 19 мест `Aspect.values()` — метод сохранён, возвращает встроенные + аддон-аспекты;
- `switch` по аспекту в кодовой базе ровно два — `wand/WandVis.java:32` (`get`) и `:44` (`with`), оба переписаны
  выше. Других `switch` с аспектовыми `case` нет (`EntityAspects.java:56` — switch по байту, `TcRecipeAspects.java:83`
  — по типу рецепта);
- `ordinal()` уходит за сеть в четырёх местах, все через сохранённый API: `entity/AspectOrb.java:41`, `:54`,
  `:132` и `menu/DeconstructionTableMenu.java:55` ↔ `:87` (`Aspect.values()[value - 1]`). Последнее — синхронизируемый
  через `ContainerData` индекс: сервер отдаёт `ordinal() + 1`, клиент читает по `values()`. Работает при условии, что
  клиент зарегистрировал аддон-аспекты до декодирования — поэтому в `AddonAspects` регистрация идемпотентна и вызывается
  из конструктора аддона, а вызов в `AspectSync.rebuild` лишь гарантирует порядок на сервере;
- `Aspect.valueOf`, `isEnum`, границ вида `<E extends Enum<...>>` для `Aspect` в кодовой базе нет; `AspectList` ключует
  аспекты в `LinkedHashMap`, то есть по ссылке, а не по ординалу;
- `getBlend()` сохранён — 48 встроенных аспектов несут то же значение `blend`, что и были (в том числе `771` у
  `ENTROPY`/`VOID`), аддон-аспекты наследуют ту же семантику.

## Ограничение API, которое стоит зафиксировать в доке

Аддон-аспект должен быть **составным**. Праймальный аспект из аддона попадает в
`Aspect.getPrimalAspects()`, который хост использует как шесть vis-слотов жезла; проверено на репорте —
такой аспект роняет 14 тестов инфузии и жезла. В Forbidden Magic все семь аспектов составные, так что
ограничение не мешает.

- Никаких изменений в контент хоста: новые аспекты не добавляются, патч открывает возможность.

Патч-файлы приложены: `0001-aspect-registry.patch`, `0002-aspect-addon-init.patch`.
```
